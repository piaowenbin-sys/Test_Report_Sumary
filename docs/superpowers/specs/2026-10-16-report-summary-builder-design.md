# Test Report Summary Builder Design

## 목적

Windows 사용자가 자동차 ECU 테스트 HTML 리포트가 들어 있는 폴더와 결과 저장 폴더를 선택한 뒤, 버튼 한 번으로 통합 서머리와 위치별 상세 리포트 및 ZIP 파일을 생성한다.

## 앱 기술과 배포

- C# .NET 10 WinForms Windows x64 앱으로 구현한다.
- 앱은 HTML 분석과 생성 로직을 직접 포함하며 PowerShell 스크립트를 호출하지 않는다.
- 기본 배포물은 MIT 라이선스의 Velopack으로 만든 일반 설치용 `Setup.exe`로 제공한다.
- 설치가 제한된 PC를 위해 self-contained 단일 EXE 휴대용 버전도 함께 제공한다.
- self-contained 배포물은 대상 PC에 별도 .NET Runtime 설치를 요구하지 않는다.
- 설치판은 시작 메뉴 바로가기와 Windows 앱 제거 기능을 제공한다.
- 코드 서명 인증서가 제공되지 않으면 서명되지 않은 내부 시험용 설치판으로 표시한다.

현재 제작 PC에는 .NET 10 Runtime은 있지만 SDK와 WiX 제작 도구가 없으므로 빌드 단계에서 설치가 필요하다.

## UI

단일 창으로 구성한다.

- 입력 폴더 선택
- 저장 폴더 선택
- 발견된 유효 HTML 리포트 개수 표시
- `서머리·ZIP 생성` 버튼
- 처리 상태와 결과 경로 표시

설정, 필터, 편집 기능은 추가하지 않는다.

## 내부 구성

- `ReportParser`: Vector HTML에서 프로젝트, 위치, 시험 항목과 결과를 읽는다.
- `ReportValidator`: 차종, 중복 위치, 필수 메타데이터를 검사한다.
- `SummaryGenerator`: 가벼운 통합 서머리와 상세 HTML 복사본을 만든다.
- `ZipPackager`: 활성 HTML만 ZIP으로 묶고 파일 수와 해시를 확인한다.
- `MainForm`: 폴더 선택, 생성 실행, 팝업과 상태 표시만 담당한다.

## 입력 검색

- 선택한 입력 폴더의 원본 Vector HTML 테스트 리포트를 자동 검색한다.
- 리포트 개수는 2개, 4개 또는 그 이상을 허용한다.
- 생성된 통합 서머리, 상세 출력 폴더, ZIP, `.bak_*` 파일은 입력에서 제외한다.
- v1에서는 HTML만 읽고 XML은 사용하지 않는다.

## 차종 검증

- 모든 입력 리포트의 `Var_Project` 값을 비교한다.
- 값이 둘 이상이면 생성을 시작하지 않는다.
- 팝업 제목은 `리포트 조합 오류`로 한다.
- 팝업 본문은 `동일 차종의 리포트가 아닙니다.`와 발견된 차종 목록을 표시한다.
- `Var_Drive_Type`, `Var_SBCM_Position`, `Var_EOL_Variant_Type` 차이는 이 팝업의 조건으로 사용하지 않는다.
- 동일 위치가 중복되거나 필수 메타데이터가 없으면 별도의 입력 오류로 중단한다.

## 생성 결과

- 가벼운 통합 서머리 HTML 1개
- 입력 리포트별 상세 HTML N개
- 위 파일만 포함한 ZIP 1개
- 메인 서머리에서 각 상세 HTML을 새 창으로 열 수 있다.
- 기존 동일 이름 출력이 있으면 타임스탬프 백업 후 교체한다.

## 검증과 실패 처리

- 상세 HTML 해시는 입력 원본과 일치해야 한다.
- 메인 HTML의 상세 링크가 모두 실제 파일로 연결되어야 한다.
- ZIP의 HTML 개수는 `1 + 입력 리포트 수`여야 한다.
- 생성 또는 검증 실패 시 기존 결과를 교체하지 않고 오류 팝업을 표시한다.
- 성공 시 생성 파일 수, ZIP 경로, 메인 서머리 경로를 표시한다.

## 테스트

- 임의 개수 입력에 대해 `1 + N` HTML과 ZIP 생성
- 서로 다른 `Var_Project` 입력 시 요청한 팝업 문구와 생성 중단
- LHD/RHD 차이는 차종 불일치로 처리하지 않음
- 중복 위치와 누락 메타데이터 거부
- 원본 및 상세 파일 해시 일치
- 링크 누락, 백업 누락, ZIP 파일 수 오류 검출
